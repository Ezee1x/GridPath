## Additional requested attributes

Electrical subattributes use the existing structured fields rather than duplicate metrics: wire count → phase; manufacturer/model/bus/breaker → panelRating/breaker; transformer kVA/voltages/phase/identifier → transformerCapacity/transformerId; meter manufacturer/model/identifier/ratings → meterModel/meterId; pole ID → utilityPole; CT cabinet → poi; electrical room → room; single-line availability → singleLine. Extraction remains partial where labels are absent.

Tariff customer charge, energy/demand tiers, seasonal/TOU schedules, ratchets, dates and restrictions remain in the original published tariff structure. Consumption interval timestamps/durations/kWh/kW, coverage and quality live in the central record energy import with original file hash. Requirements, plan-sheet mappings, code editions, source directory and measured benchmark metadata are derived from this same record.

## Completed master milestones

- Foundation: shared field IDs and lossless optional metadata; requirements and coverage are derived from central fields, not separately maintained per-site checklists.
- Public rates: OpenEI v7 paired Census lat/lon, sector filters, full detail on request, bounded requests/retry/cache, partial results, preserved raw rate structures and bill-evidence confirmation. Missing OPENEI_API_KEY explicitly blocks live rate access.
- Customer intake: CSV and a restricted linked ESPI/Green Button subset; local parsing, unit/timezone validation, actual interval durations, gaps/duplicates, monthly apportionment, one meter/channel, modeled-data exclusion.
- Documents: existing local PDF text and image OCR; strict field schemas; evidence page/excerpt, existing/proposed/unknown classification, acceptance/edit/rejection history. Explicit local scanned-PDF OCR is bounded to three low-text pages; unprocessed pages remain flagged. No cloud vision service is configured or used.
- Requirements/records: requirements-to-evidence matrix, reference-drawing import guidance, municipal directory, official/reference-only code library, safe copyable information requests, JSON/ZIP extensions and printable HTML.
- Quality: measured source-operation timings and explicit manual baseline; no fabricated savings. See eqore-demo-validation.md and eqore-live-results.json.

### Reference upload safeguard

On `codex/eqore-master-intake`, uploads can be explicitly marked reference-only before attachment. Generic/proposed plan files keep missing-data requests and verified selections unchanged, and cannot be used to accept existing electrical conditions, confirm customer tariffs, or supply actual usage. Classification and original file references are retained in export. Existing unclassified uploads are preserved. Actual EQORE files remain pending user supply/import.
